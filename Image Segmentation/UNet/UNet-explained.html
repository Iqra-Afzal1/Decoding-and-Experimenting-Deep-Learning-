U-Net, explained step by step

U-Net gives every pixel of an image a label, such as "tumour" or "background". For each pixel it has to answer two questions: what object is this? and where exactly is the object's border? The left half of the U answers the first question. The right half answers the second. Click any block or arrow in the diagram to read what happens there.

The U-Net at a glance

How to read the sizes on this page "128×128, 128 maps" means 128 grids, each 128 cells wide and 128 cells tall. One map is one grid of numbers. It is made by one filter and shows where that filter found its feature (for example a vertical edge). Going down the U, each grid gets smaller and the number of maps gets bigger.

1The task: a label for every pixel

A classifier looks at a whole image and says one word: "cat". Segmentation is harder. We have to say, for every single pixel, which class it belongs to.

First idea: just look at each pixel's brightness?

Take our example image: a bright circle (the object), an equally bright square (not the object), and a dark background. Suppose our rule is "bright pixel = object".

PixelBrightnessRule saysTruth
inside circle0.85objectobject ✔
background0.20backgroundbackground ✔
inside square0.85objectbackground ✘

But hold on, the square isn't the object! Both pixels have exactly the same brightness, so no rule that looks at one pixel can ever tell them apart. The only difference is the shape around them: one sits inside something round, the other inside something square.

Second idea: look at a big area around every pixel?

Yes, that fixes the square problem. U-Net does this by shrinking the image in steps. After shrinking, one cell stands for a block of many pixels, so a feature map covers a large part of the image.

But shrinking has a cost: a small grid cannot store the exact position of the circle's border. So we need a small grid to recognise the object, and a full-size grid to draw its border. U-Net uses both:

The whole idea in two lines Encoder (left side of the U): shrinks the image step by step to recognise what is in it. Exact positions are lost.
Decoder (right side): receives these feature-rich maps and enlarges them. Enlarging alone can't recover exact positions, so at each size it takes spatial information from the encoder's saved maps (skip connections) and combines both into new maps. The last maps give the mask.

2Filters: what a feature really is

"The encoder extracts features". But what is a feature, actually? Let's decode it.

A filter is a small grid of weights. For example, a filter for vertical edge (given in figure below): negative weights on the left column, zero in the middle, positive on the right. Place it on 3×3 pixels, multiply each pixel by the weight on top of it, and add everything up.

So the result is a match score: it is high when the pixels match what the filter looks for. Now slide the filter over every position and write down the score each time. The grid of scores is a feature map.

Therefore, a feature map is not a picture of the image. It is a map of where one filter found its feature. After that, a step called ReLU changes every negative score to 0. Then the map only shows where the feature is.

Hover over (or tab to) any output cell to see the 9 pixels it used.

But these are only edges. How do we get to "circle"?

The first layer has 64 filters, so it makes 64 maps. The second layer does not look at pixels. Its filters are slid over those 64 maps. So a second-layer filter can check, for example, "horizontal edge above, vertical edge on the left". That combination is a corner. Each layer builds on the maps of the layer before:

These filters are not written by hand. They are learned during training.

3Shrinking (max pooling): what do we lose?

Shrinking halfs each map. Take one block:

Block valuesKept
1, 3, 4, 99
9, 3, 4, 19
1, 9, 4, 39

But hold on, the 9 was in a different place each time and the result didn't change! After shrinking, the network knows "the feature was found somewhere in this block" but not where in the block.

Is that bad?

For what, it is fine: the network only needs to know that the feature is present. For where, it is a loss. Each shrink doubles the uncertainty: after 1 shrink the position is known to within 2 pixels, then 4, then 8, and after 4 shrinks only to within 16 pixels.

Click a cell to move the 9 around and watch the small map.

4What the decoder receives

The encoder hands its final maps to the decoder: 16×16, 1024 channels. At each of the 16×16 locations there are 1024 numbers describing what is there, for example "part of a round object".

A location(single cell) knows its original block (of 256 pixels) contains part of the circle, but not which of its 256 pixels do.

Why not make the mask directly from these maps?

We could label each of the 256 locations and stretch the result to full size. But we need pixel prediction on original image input.

So the decoder does two things, over and over:

  1. Enlarge the feature-rich maps (tab 5).
  2. Take spatial information from the encoder and combine it with them (tab 6).

How one cell is enlarged

Each cell becomes 2×2 = 4 cells. Each new value is the old value multiplied by one of 4 learned weights.

Old value4 weights4 new values
21, 1, 1, 12, 2, 2, 2 (plain copy)

Why enlarge?

Two reasons. 1. The mask must end at 256×256 (original image size). 2. Decoder stacks these maps with the encoder's 32×32 maps, which is only possible when both grids are the same size.

Is enlarging enough?

No. The same 4 weights are used for every cell of every image, so they cannot know spatial information in this image. The enlarged maps still know what, but the where is still blocky.

The missing spatial information must come from somewhere else - and comes from encoder.

6Step 2: take spatial information from the encoder

Before each shrink, the encoder saved its maps. The saved 32×32 maps were made before any further shrinking, so they still hold spatial information of this level. They are sent to the decoder through the skip connection.

Stack

The two sets are placed side by side. At one location: 512 numbers from the decoder + 512 from the encoder = 1024 numbers. Nothing is calculated yet.

Combine with filters

3×3 filters slide over the stacked maps. At each location, one filter multiplies all 1024 numbers at a cell by its corresponding learned weight, adds them into one number, and sets negatives to 0. There are 512 filters, so the result is 512 new feature maps.

These weights are learned by making mask at last level, then finding loss and then updating all weights in decoders.

The weights decide how what and where are mixed. For example, a filter can learn to give a high value only where the decoder maps say "object nearby" and the encoder maps say "edge exactly here". That marks the true border pixel.

7Worked example: from maps to the final answer

The decoder path with real numbers: one row of 8 pixels, 2 saved encoder maps, 1 decoder map, one combining filter and one final score. The real network does the same steps with more pixels and maps.

Press Next to go one step at a time. Click any pixel column to see its own calculation.

What happened

The enlarged decoder map knew which region is the object, but its border was stuck at the edge of a 4-pixel block, so it missed pixel 4. The saved edge map knew exactly where brightness jumps, but it also reacted to the speck at pixel 2.

The combining filter added the decoder map, the edge map and the brightness of the next pixel into one sum. Pixel 4 has an edge and a bright pixel after it, so its sum is above zero. Pixel 2 has an edge but a dark pixel after it, so its sum is below zero. Then the final score turned each value into a percentage.

8Pixel prediction: from 64 numbers to the mask

The last decoder block outputs 256×256 locations, each with 64 numbers. Location (x, y) matches pixel (x, y). These 64 numbers do not say "object" directly; they are the information needed to decide it.

Step 1: one score per location

Multiply the 64 numbers by 64 learned weights and add them up, plus a fixed number. The same weights are used at every location. (This is a 1×1 filter: a filter that looks at one location only.)

Step 2: score to probability

The score is squeezed into a probability between 0% and 100% (with a function called sigmoid):

Score−4−20+2+4
Probability of object2%12%50%88%98%

Step 3: label

Above 50% → object, otherwise background. Doing this at all 65,536 locations gives the mask.

Our two pixels from tab 1

Using 3 of the 64 numbers, with weights object score = 8 × context + 0.5 × edge + 0.5 × brightness − 4.5:

The scoring is simple. It works only because the decoder already put the right numbers into each location. Without context, both pixels would get the same score, and one would be wrong.

More than two classes

With cat, dog and background, the network computes 3 scores per location, each with its own 64 weights. The scores become percentages that add up to 100% (with a function called softmax), and the highest wins:
